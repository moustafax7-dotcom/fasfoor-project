# مطعم فسفور — Fasfoor Seafood Restaurant

مشروع Full-stack (واجهة عميل + لوحة إدارة) لمطعم مأكولات بحرية بفرعين (مدينة نصر والجبل الأصفر).

## الستاك
- **Front-end:** React (Vite) + React Router
- **Back-end:** Node.js + Express
- **Database:** MongoDB (Mongoose)

## هيكل المشروع
```
fasfoor-project/
├── client/     → React app (واجهة العميل + لوحة الإدارة)
├── server/     → Node/Express API
└── docs/       → ملفات مرجعية
```

## التشغيل محليًا

### 1) السيرفر
```bash
cd server
cp .env.example .env      # عدّل MONGO_URI حسب بيئتك (Atlas أو محلي)
npm install
npm run seed               # يعبّي بيانات حقيقية: فروع، منيو، أدمن تجريبي، كوبون، ولاء...
npm run dev                # http://localhost:5000
```

### 2) الفرونت
```bash
cd client
cp .env.example .env
npm install
npm run dev                # http://localhost:5173
```

## بيانات الدخول بعد تشغيل npm run seed
| النوع | القيمة |
|---|---|
| أدمن (super_admin) | `admin@fosfor.com` / باسورد عشوائي بيتطبع في الـ console مرة واحدة وقت `npm run seed` |
| عميل تجريبي | `01012345678` — الدخول عبر OTP (الكود هيظهر في console السيرفر لأن SMS الحقيقي مش متصل بعد) |
| كود خصم تجريبي | `FOS20` (خصم 20%) |

⚠️ `npm run seed` بيمسح البيانات الحالية في المجموعات المستهدفة قبل ما يعيد إدخالها — استخدمه بس في بيئة تطوير.

## ✅ الحالة الحالية (تم التحقق فعليًا)
- واجهة العميل كاملة: رئيسية، منيو، تفاصيل صنف (مقاسات+إضافات)، سلة، فروع، عروض، تسجيل دخول OTP، حسابي، طلباتي، تتبع الطلب، المفضلة، العناوين، نقاط الولاء، الإحالة
- لوحة الإدارة كاملة: دخول، Dashboard، الطلبات (Kanban)، الأصناف والأسعار، المخزون، الفروع، العروض، الكوبونات والولاء، المندوبين ومناطق التوصيل، شاشة المطبخ (KDS)، العملاء، التقارير، صلاحيات الموظفين، سجل تغييرات الأسعار، الإعدادات
- الباك إند: 15 موديل، 17 كنترولر، 19 راوت — كلهم متصلين فعليًا بدون بيانات وهمية
- `npm install` و`npm run build` تم التحقق منهم بنجاح لكل من السيرفر والفرونت (201 موديول React اتحولوا من غير أي خطأ)

## 🔒 إصلاحات أمنية وبيزنسية جوهرية تمت
- **الدخول بـ OTP فقط**: اتشالت نهائيًا آلية الدخول بباسورد اختياري (كانت ثغرة تسمح لأي حد يعرف رقم تليفون عميل إنه يدخل حسابه)
- **الطلب مربوط بالعميل من التوكن**، مش من بيانات الفرونت — يمنع انتحال شخصية عميل تاني
- **رسوم توصيل حقيقية** حسب منطقة العميل بدل رقم ثابت
- **فحص حالة الفرع** (مفتوح/مقفول) قبل السماح بالطلب
- **منع خلط أصناف من فرعين مختلفين** في نفس الطلب
- **حد أدنى لقيمة الطلب** لكل فرع
- **الكوبون والخصم يتحققوا على السيرفر دايمًا**، مش من الفرونت
- **إعادة الطلب** و**التقييم بعد التسليم** و**برنامج الإحالة** شغالين فعليًا

## ملاحظات أمان تمت مراجعتها
- **التوكن (JWT) متخزن في localStorage** — قرار واعي: مفيش نقطة XSS فعلية في الكود حاليًا (لا `dangerouslySetInnerHTML` ولا `eval`)، فالتحويل لـ httpOnly cookies (اللي محتاج CSRF protection كامل) مؤجل لحد ما يظهر سبب حقيقي ليه.
- **تسعير الطلب بالكامل بيتحسب من قاعدة البيانات في السيرفر**، مش من أي رقم جاي من الفرونت (`orderController.js::createOrder`).
- **`GET /api/orders/:id` محمي بتوكن العميل** مع تحقق ملكية الطلب.
- **Rate limiting مفعّل** على `/otp/send`, `/otp/verify`, `/admin/auth/login` + قفل بعد 5 محاولات كود خاطئة لكل رقم.
- **باسورد الأدمن الافتراضي بيتولّد عشوائيًا** وقت `npm run seed`، مش مكتوب ثابت في الكود.

## ملاحظات مهمة من متطلبات الإدارة
- كل صنف لازم يترتبط بفرع واحد على الأقل (`Item.branches`)
- الأصناف بالوزن ليها حقل `weightPrices` منفصل (ربع/نص/كيلو)
- أي تعديل في السعر بيلغي اعتماد السعر تلقائيًا (`isPriceApproved: false`) ويتسجل في سجل تغييرات الأسعار
- قسم العملاء يعرض بيانات طلبات حقيقية فقط — بدون تقييمات مُختلقة
